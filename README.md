# YOLO 객체탐지 실습: 임계값을 바꾸면 무엇이 사라질까

사진 한 장을 YOLO로 detection(박스)과 segmentation(마스크)에 돌리고, 신뢰도 임계값(`conf`)을 0.25 / 0.50 / 0.70으로 바꿔 가며 오탐과 미탐을 확인했습니다.

## 실행 방법

```
python -m venv .venv
.venv\Scripts\activate
pip install ultralytics
python run_yolo.py input/<사진 파일>
```

- 모델: `yolo26n.pt`(detection), `yolo26n-seg.pt`(segmentation). 처음 실행할 때 자동으로 내려받습니다.
- 설정: `imgsz=640`, `device=cpu`, `conf` 0.25 / 0.50 / 0.70
- 결과: `outputs/yolo/<사진 이름>/`에 결과 이미지(`.jpg`), 박스·점수 JSON, 마스크 PNG, `manifest.json`(입력 파일, 모델·패키지 버전, 설정)
- 실행 환경: Windows 11, Python 3.12.10, ultralytics 8.4.208, CPU만 사용

## 사용한 사진

| 사진 | 출처·공유 조건 |
|---|---|
| `bus.jpg` | 과제에서 제공한 Ultralytics 예제 사진 |
| `20251012_082929.jpg` (음식) | 직접 촬영한 사진, 사람 없음 |
| `20260329_173924.jpg` (거울 방) | 직접 촬영한 사진 (원본과 결과 이미지는 이 저장소에 포함하지 않음) |

## 결과 1. 음식 사진 (주 사례)

**예상:** 음식을 올바르게 찾을 줄 알았습니다.

**의외였던 점**

- 음식을 올바른 이름으로 찾은 것이 하나도 없었습니다. 맞게 찾은 것은 그릇, 포크, 나이프, 식탁뿐이었습니다.
- 모델이 모르는 이름이 이렇게 많을 줄은 몰랐습니다. 레몬은 `orange`, 케이크는 `sandwich`로 불렀고, 치즈·훈제연어·포도는 아예 이름이 없어서 찾지 못했습니다. 모델이 아는 이름은 정해져 있고, 모르는 물체에는 비슷한 이름을 붙인다는 점을 이번에 알았습니다.

**detect 결과**

| 물체 | 점수 | 정답 여부 | 0.50 | 0.70 |
|---|---|---|---|---|
| 요거트 그릇 `bowl` | 0.92 | 맞음 | 남음 | 남음 |
| 국 그릇 `bowl` | 0.90 | 맞음 | 남음 | 남음 |
| 나이프 `knife` | 0.87 | 맞음 | 남음 | 남음 |
| 포크 `fork` | 0.76 | 맞음 | 남음 | 남음 |
| 식탁 `dining table` | 0.75 | 맞음 | 남음 | 남음 |
| 케이크 조각 → `sandwich` | 0.52 | 틀림(오탐) | 남음 | 사라짐 |
| 레몬 조각 → `orange` | 0.31 | 틀림(오탐) | 사라짐 | 사라짐 |

박스 수는 0.25에서 7개, 0.50에서 6개, 0.70에서 5개입니다.

**발견한 오류**

- **오탐:** 레몬을 `orange`(0.31)로, 케이크를 `sandwich`(0.52)로 잘못 불렀습니다. 레몬은 학습한 이름에 없어서 가장 비슷한 이름이 붙었다고 해석합니다.
- **미탐:** 브로콜리 샐러드는 `broccoli`가 YOLO가 아는 이름인데도 찾지 못했습니다. 치즈, 훈제연어, 포도는 클래스에 없어서 찾지 못했고, 오른쪽 가장자리에 반쯤 보이는 숟가락도 찾지 못했습니다.
- **임계값의 효과:** 0.50에서 레몬 오탐이, 0.70에서 케이크 오탐이 사라졌습니다. 정답 박스 5개는 점수가 0.75 이상이라 0.70까지 모두 남았습니다. 이 사진에서는 0.70이 정탐을 잃지 않고 오탐만 걸러 냈습니다.

**segment 결과**

- 박스 수는 0.25와 0.50에서 6개, 0.70에서 5개입니다.
- 케이크를 `sandwich`로 본 오탐이 0.72로 올라가 0.70에서도 남고, 정답인 식탁(0.64)은 0.70에서 사라졌습니다.
- 같은 사진이라도 모델에 따라 오탐이 남는 선이 다릅니다.

## 결과 2. 거울 방 사진 (추가 실험)

이 사진의 원본과 결과 이미지는 이 저장소에 올리지 않았고, 아래에는 점수와 관찰 내용만 적었습니다.

**예상:** 거울에 비친 나도 찾는지 알아보려고 일부러 찍었습니다.

| 모델 | conf 0.25 | conf 0.50 | conf 0.70 |
|---|---|---|---|
| detect | person 0.91 (1개) | 1개 | 1개 |
| segment | person 0.90, cake 0.31 (2개) | 1개 | 1개 |

- **정탐:** 거울 밖의 진짜 사람은 두 모델 모두 `person`으로 찾았습니다.
- **오탐:** segment 0.25에서 왼쪽 볼록거울이 `cake`(0.31)로 잡혔고, 0.50에서 사라졌습니다.
- **미탐:** 거울 속에 비친 사람 모습은 어느 모델도 찾지 못했습니다. 별도 실험으로 detect를 `conf=0.05`까지 낮춰도 거울 속 사람은 후보에도 오르지 못했고, 오른쪽 거울이 `sports ball`(0.13)로 잡혔습니다. 이 0.05 실험은 `run_yolo.py` 밖에서 따로 실행했습니다.
- **해석(추측):** 왼쪽 거울 속 상은 거꾸로 누워 휘어져 있고, 오른쪽 거울 속 상은 손 일부만 작게 보여서 사람 모양으로 읽히지 않는 것 같습니다. 확인한 원인은 아니고 이미지에서 본 점입니다.

## 결과 3. 버스 예제 사진

- 박스 수: detect·segment 모두 0.25와 0.50에서 5개, 0.70에서 4개
- 점수: bus 0.86, person 0.88 / 0.86 / 0.81 / 0.65
- 0.70에서 사라진 것은 화면 왼쪽 가장자리에서 몸이 잘린 사람(0.65)입니다. 실제로 있는 사람이 사라졌으니 **미탐이 하나 늘어난** 경우입니다.
- 마스크는 버스와 사람의 윤곽을 따라 칠해졌고, 박스 안에 있던 배경은 빠졌습니다.

## 정리

1. 임계값을 올리면 점수가 낮은 박스부터 사라집니다. 음식 사진에서는 오탐이, 버스 사진에서는 실제 사람이 먼저 사라졌습니다. 어느 쪽이 사라지는지는 사진에 달려 있습니다.
2. confidence는 정답 확률이 아닙니다. 케이크를 `sandwich`로 본 점수가 0.52(detect), 0.72(segment)로 서로 달랐고, 둘 다 틀린 박스입니다.
3. 모르는 물체에는 아는 이름 중 비슷한 것을 붙입니다(레몬 → `orange`, 거울 → `cake`, `sports ball`).
4. 같은 사진에서 detect와 segment의 결과가 다를 수 있습니다.

## 한계와 확인하지 못한 것

- 사진 3장, 모델 2개로 본 것이라 모델 전체의 성능을 말할 수는 없습니다. 정답 박스를 만들어 두고 정밀도·재현율이나 mAP를 계산하지는 않았습니다.
- 마스크 이미지는 직접 열어 확인하지 못한 것이 있고, 일부 결과는 JSON 점수로만 확인했습니다.
- 원인에 대한 해석은 이미지를 보고 추측한 것입니다.
