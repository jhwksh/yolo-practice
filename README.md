# YOLO 객체탐지 실습: 임계값을 바꾸면 무엇이 사라질까

사진을 YOLO로 detection(박스)과 segmentation(마스크)에 돌리고, 신뢰도 임계값(`conf`)을 0.25 / 0.50 / 0.70으로 바꿔 가며 오탐과 미탐을 확인했습니다.

## 채점 기준별로 볼 곳

| 채점 기준 | 이 문서에서 보는 곳 |
|---|---|
| 실행 가능성 | "실행 방법"(명령어, 실행 위치와 환경, `requirements.txt`, 새로 복제한 폴더에서 재실행한 확인), `outputs/`의 결과 파일과 `manifest.json` |
| 원본 대조·근거 | 결과 1과 결과 3의 "검토 기록" 표(원본 좌표, 원본에서 본 것, 판정, 수정 내역 없음, 확인 필요 여부) |
| 범위 정직성 | "한계와 확인하지 못한 것"(처리한 범위, 직접 본 결과와 보지 않은 결과, 추측인 부분), 검토 기록 표의 "못 찾음" 행 |
| 설명 | "도구와 설정을 고른 이유"(실행 위치, 모델·`conf`·`imgsz`를 고른 이유와 실제 결과의 연결) |

## 실행 방법

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python run_yolo.py input/<사진 파일>
```

- PowerShell에서 `activate`가 실행 정책 때문에 막히면, 활성화하지 않고 `.venv\Scripts\python.exe run_yolo.py input/<사진 파일>`처럼 직접 실행해도 됩니다. 이번 실습은 이 방식으로 실행했습니다.
- 모델: `yolo26n.pt`(detection), `yolo26n-seg.pt`(segmentation). 처음 실행할 때 자동으로 내려받습니다.
- 설정: `imgsz=640`, `device=cpu`, `conf` 0.25 / 0.50 / 0.70
- 결과: `outputs/yolo/<사진 이름>/`에 결과 이미지(`.jpg`), 박스·점수 JSON, 마스크 PNG, `manifest.json`(입력 파일, 모델·패키지 버전, 설정)
- 실행 위치와 환경: 내 로컬 PC(Windows 11), Python 3.12.10, ultralytics 8.4.208, CPU만 사용(GPU 없음). 같은 내용이 `manifest.json`의 `run_location`, `versions`에도 기록됩니다.
- 입력 사진: `input/` 폴더는 저장소에 올리지 않았습니다. 버스 예제는 `curl -L -o input/bus.jpg https://ultralytics.com/images/bus.jpg`로 받을 수 있고, 음식·거울 사진은 개인 촬영본이라 올리지 않았습니다. 대신 결과 이미지에서 원본 위에 그려진 결과를 볼 수 있습니다.
- 재실행 확인: 이 저장소를 새 폴더에 복제(clone)하고 버스 사진을 `input/`에 넣어 `run_yolo.py`를 실행해, 같은 결과(detect·segment 모두 박스 5개, 5개, 4개)와 결과 파일 16개가 다시 만들어지는 것을 확인했습니다. 같은 PC의 기존 가상환경을 썼고, 새 가상환경에 `requirements.txt`를 처음부터 설치하는 과정까지는 시험하지 않았습니다.
- Windows에서 처음 실행할 때 `c10.dll` 로드 실패 오류와 함께 "Microsoft Visual C++ Redistributable is not installed"라는 메시지가 나오면 [Microsoft Visual C++ 재배포 가능 패키지(x64)](https://aka.ms/vs/17/release/vc_redist.x64.exe)를 설치한 뒤 다시 실행합니다. 이번 실습에서 실제로 겪은 오류입니다.

## 결과 1. 음식 사진 (주 사례)

**예상:** 음식을 올바르게 찾을 줄 알았습니다.

**의외였던 점**

- 음식을 올바른 이름으로 찾은 것이 하나도 없었습니다. 맞게 찾은 것은 그릇, 포크, 나이프, 식탁뿐이었습니다.
- 모델이 모르는 이름이 이렇게 많을 줄은 몰랐습니다. 레몬은 `orange`, 케이크는 `sandwich`로 불렀고, 치즈·훈제연어·포도는 아예 이름이 없어서 찾지 못했습니다. 모델이 아는 이름은 정해져 있고, 모르는 물체에는 비슷한 이름을 붙인다는 점을 이번에 알았습니다.

**detect 결과**

| 물체 | 점수 | 정답 여부 | 0.50 | 0.70 |
|---|---|---|---|---|
| 요거트 그릇 `bowl` | 0.92 | 맞음 | 남음 | 남음 |
| 국 그릇 `bowl` | 0.90 | 맞음 | 남음 | 남음 |
| 나이프 `knife` | 0.87 | 맞음 | 남음 | 남음 |
| 포크 `fork` | 0.76 | 맞음 | 남음 | 남음 |
| 식탁 `dining table` | 0.75 | 맞음 | 남음 | 남음 |
| 케이크 조각 → `sandwich` | 0.52 | 틀림(오탐) | 남음 | 사라짐 |
| 레몬 조각 → `orange` | 0.31 | 틀림(오탐) | 사라짐 | 사라짐 |

박스 수는 0.25에서 7개, 0.50에서 6개, 0.70에서 5개입니다.

**발견한 오류**

- **오탐:** 레몬을 `orange`(0.31)로, 케이크를 `sandwich`(0.52)로 잘못 불렀습니다. 레몬은 학습한 이름에 없어서 가장 비슷한 이름이 붙었다고 해석합니다.
- **미탐:** 브로콜리 샐러드는 `broccoli`가 YOLO가 아는 이름인데도 찾지 못했습니다. 치즈, 훈제연어, 포도는 클래스에 없어서 찾지 못했고, 오른쪽 가장자리에 반쯤 보이는 숟가락도 찾지 못했습니다.
- **임계값의 효과:** 0.50에서 레몬 오탐이, 0.70에서 케이크 오탐이 사라졌습니다. 정답 박스 5개는 점수가 모두 0.74보다 높아서(가장 낮은 식탁이 0.7461) 0.70까지 모두 남았습니다. 이 사진에서는 0.70이 정탐을 잃지 않고 오탐만 걸러 냈습니다.

**segment 결과**

- 박스 수는 0.25와 0.50에서 6개, 0.70에서 5개입니다.
- 케이크를 `sandwich`로 본 오탐이 0.72로 올라가 0.70에서도 남고, 정답인 식탁(0.64)은 0.70에서 사라졌습니다.
- 같은 사진이라도 모델에 따라 오탐이 남는 선이 다릅니다.

**검토 기록: 원본과 대조한 내용**

## 결과 2. 거울 방 사진 (추가 실험)

이 사진의 원본과 결과 이미지는 이 저장소에 올리지 않았고, 아래에는 점수와 관찰 내용만 적었습니다.

**예상:** 거울에 비친 나도 찾는지 알아보려고 일부러 찍었습니다.

| 모델 | conf 0.25 | conf 0.50 | conf 0.70 |
|---|---|---|---|
| detect | person 0.91 (1개) | 1개 | 1개 |
| segment | person 0.90, cake 0.31 (2개) | 1개 | 1개 |

- **정탐:** 거울 밖의 진짜 사람은 두 모델 모두 `person`으로 찾았습니다.
- **오탐:** segment 0.25에서 왼쪽 볼록거울이 `cake`(0.31)로 잡혔고, 0.50에서 사라졌습니다.
- **미탐:** 거울 속에 비친 사람 모습은 어느 모델도 찾지 못했습니다. 별도 실험으로 detect를 `conf=0.05`까지 낮춰도 거울 속 사람은 후보에도 오르지 못했고, 오른쪽 거울이 `sports ball`(0.13)로 잡혔습니다. 이 0.05 실험은 `run_yolo.py` 밖에서 따로 실행했습니다.
- **해석(추측):** 왼쪽 거울 속 상은 거꾸로 누워 휘어져 있고, 오른쪽 거울 속 상은 손 일부만 작게 보여서 사람 모양으로 읽히지 않는 것 같습니다. 확인한 원인은 아니고 이미지에서 본 점입니다.

## 정리

1. 임계값을 올리면 점수가 낮은 박스부터 사라집니다. 음식 사진에서는 오탐이, 버스 사진에서는 실제 사람이 먼저 사라졌습니다. 어느 쪽이 사라지는지는 사진에 달려 있습니다.
2. confidence는 정답 확률이 아닙니다. 케이크를 `sandwich`로 본 점수가 0.52(detect), 0.72(segment)로 서로 달랐고, 둘 다 틀린 박스입니다.
3. 모르는 물체에는 아는 이름 중 비슷한 것을 붙입니다(레몬 → `orange`, 거울 → `cake`, `sports ball`).
4. 같은 사진에서 detect와 segment의 결과가 다를 수 있습니다.

## 도구와 설정을 고른 이유

- **실행 위치: 내 로컬 PC.** GPU가 없어서 CPU로 실행했습니다.
- **모델 `yolo26n.pt`, `yolo26n-seg.pt`:** 과제에서 지정한 가장 작은(n) 모델이고, CPU만으로도 사진 한 장을 부담 없이 처리할 수 있어서 이대로 썼습니다.
- **detect와 segment를 모두 실행:** 박스는 "어디에 있는가"를, 마스크는 "경계가 어디까지인가"를 보여 줍니다. 이번 사진 중 음식 사진에서는 식탁 마스크가 사진 대부분을 덮는 것을 마스크로 확인할 수 있었습니다.
- **`conf` 0.25 / 0.50 / 0.70:** 0.25는 Ultralytics의 기본값이고, 0.50은 과제에서 비교하라고 한 값입니다. 버스 사진에서는 0.25와 0.50의 박스 수가 같아서 임계값의 효과를 보려고 더 높은 0.70을 추가했습니다.
- **`imgsz=640`:** 과제에서 지정한 입력 크기입니다.
- **결과와의 연결:** 음식 사진의 detect 결과에서는 0.70이 오탐 2개를 걸러내고 맞는 박스 5개는 남겨서 알맞은 선이었습니다. 하지만 버스 사진에서는 같은 0.70이 실제 사람 한 명을 잃게 했습니다. 알맞은 임계값은 사진과 모델에 따라 달라서, 하나의 값을 모든 사진에 쓸 수는 없었습니다.

## 한계와 확인하지 못한 것

**처리한 범위**

- 사진 3장(이 저장소에는 버스·음식 2장의 결과만 있음) × 모델 2개 × `conf` 3개 = 18회 실행했습니다.
- 정답 박스를 만들어 두지 않았기 때문에 정밀도·재현율·mAP 숫자는 계산하지 않았습니다. 맞고 틀림은 원본 사진을 보고 사람이 판정한 것입니다.
- 사진 3장, 모델 2개로 본 것이라 모델 전체의 성능을 말할 수는 없습니다.

**눈으로 직접 확인한 결과**

- 음식 사진: `detect_conf0.25.jpg`, `segment_conf0.70.jpg`, `segment_conf0.25_mask.png`
- 버스 사진: `detect_conf0.70.jpg`, `segment_conf0.25.jpg`

**열어 보지 않고 JSON 점수와 박스 수로만 확인한 결과**

- 음식 사진의 `detect_conf0.50.jpg`, `detect_conf0.70.jpg`, `segment_conf0.25.jpg`, `segment_conf0.50.jpg`, 그리고 `segment_conf0.50_mask.png`, `segment_conf0.70_mask.png`
- 버스 사진의 나머지 결과 이미지와 마스크
- 위 표에 "못 찾음"으로 적은 브로콜리 샐러드와 숟가락의 위치는 이미지에서 눈으로 본 것이고, 해당 부분에 낮은 점수의 후보가 있었는지는 `conf` 0.25 아래로 내려서 확인하지 않았습니다(거울 방 사진에서만 `conf=0.05`를 따로 시험했습니다).
